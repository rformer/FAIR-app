# F-005 Monte Carlo Simulation Engine — Tasks
Status: **Approved** (Robert Former, 2026-11-10) | Design: Approved 2026-11-10

Sizing: S ≤ 1 day · M = 2–3 days · L = up to 1 week (split when picked up).
Prerequisites: F-001 (RBAC, `analysis.*` permissions, keys, the gateway), F-002 (audit trail), F-003 (scenarios, input bundles, move and archive), F-015 (settings, release manifest). All are done.
Every task that adds a migration follows the immutability rule. Every new event type gets a catalog entry with the task that first emits it. Every new route is linted by `scripts/openapi-lint.sh`. Every new BU-owned table gets an `rlstest` fixture. Every engine change runs the engine CI job (lint, types, tests, validation suite).

- 2026-11-10: T-02 (migrations 0101 to 0103; ADR-007 amendment 4, decided with Robert Former): River schema `risk_river`; schema `analysis` with bootstrap role `analysis_definer` (re-run `scripts/db-bootstrap.sh`). Analysts request through the invoker functions `analysis.request_run` (iteration bounds and the active-run limit passed from the settings; a reproduction must have the original's inputs and bundle digest) and `analysis.request_aggregate`, which insert a run with an empty result and series row per control set, or an aggregate with its members; triggers of `analysis_definer` attribute them and check the scenario under the caller's RLS. The worker's functions (`start_run` returns an attempt token that `progress`, `put_series`, `finish_run` and `fail_run` need; `start_aggregate`, `finish_aggregate`, `fail_aggregate`) and `cancel_run` change them; finished rows are immutable for every role (PF023); limits and states are PF024. Aggregates and members are visible only with every member run in the reader's read scope: `bu_restrict`, a RESTRICTIVE select policy for app_rw calling the definer function `analysis.members_visible` (two policies referring to each other recurse). The functions emit all eight §9 events, so their catalog entries came here (helper `analysis.emit`).
